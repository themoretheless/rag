# Регрессионная оценка поиска по репозиторию

Набор `data/eval/repository-v1.json` содержит 24 вручную составленных вопроса по 16 текущим документам и исходникам: русские вопросы, английские вопросы и запросы с именами функций. Для каждого выбран контрольный документ. Это начальная проверка нахождения конкретного документа, а не полная разметка всех полезных ответов и не журнал реальных пользовательских вопросов.

Запуск на отдельной временной базе:

```sh
RAG_EMBEDDING_PROVIDER=mock RAG_EMBEDDING_DIMS=32 cargo run --bin eval -- \
  --dataset data/eval/repository-v1.json --modes lex --warmup 1 --repeat 3 --json
```

Mock embeddings здесь используются только для заполнения обязательных полей корпуса. Оценивается lexical retrieval; результаты ничего не доказывают о semantic/hybrid поиске с реальной embedding-моделью.

Для данного набора один запрос соответствует одному контрольному документу; другие полезные документы могут не иметь метки. Поэтому метрики нужно читать как достижение выбранной цели поиска, а не долю всех релевантных источников. Оценщик отклоняет отсутствующие в корпусе метки, неоднозначные одинаковые имена файлов и дубли query id.

CI сохраняет отдельный JSON-отчёт рядом с существующим example eval. Новый набор пока не имеет порога, блокирующего выпуск. Отчёт с результатами локального замера и SHA-256 использованных файлов находится в `data/eval/repository-v1.baseline.json`.

Следующее расширение: реальные вопросы пользователя, полная разметка нескольких релевантных источников, отрицательные вопросы без подтверждения, устаревшие и противоречащие документы, а затем сравнение lex/hybrid/reranker на неизменном корпусе. Текущий формат оценщика требует хотя бы одну положительную метку и пока не измеряет качество отказа от ответа.
