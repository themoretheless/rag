# Python handler and else candidate routes

Value capture 7 / extraction format 87 extends `data_slice` with `try/except/else/finally`. A protected body produces normal, return, jump and conservative error-prefix completions. `else` receives only normal completion. Errors raised by `else` or a handler bypass the sibling handlers and route to finalization or an outer region. Finally retains the saved-value/updated-local behavior described in [the finalizer contract](PYTHON_FINALLY_FLOW.md).

A bare handler consumes the modeled exceptional alternative. Typed handlers retain possible matching candidates, in source order, plus an uncaught alternative unless a bare handler consumes it. `exception_type_matching_proven=false` and `exception_filter_evaluation_proven=false` are explicit: this is not a Python class-hierarchy/type solver or proof that a handler will run. Named selectors, attribute paths and tuples are supported syntactically; dynamic selector expressions and exception groups remain unavailable. Selector attributes depend on their object rather than an unrelated local with the same property name. Comments in selector tuples do not disable capture.

Each handler invocation carries its own `flow_context`, `exception_match` and abstract `caught_exception` occurrences. Relations distinguish possible matching, abstract exception-object provenance, alias binding and local filter inputs. Normal handler/else paths merge definitely initialized locals with `try_merge_input` links; incomplete initialization is not silently converted to a value. Control/exception/type candidate unions are not asserted to be one feasible execution path.

`except E as err` assigns the caught-object candidate within that handler and clears the alias on normal, return, jump and exceptional exit. A saved `return err` keeps its evaluated value; a later `finally`/continuation read of the cleared name becomes unavailable if not initialized on all captured paths. Captured bare `raise` reuses the active exception, including pending exceptional finalization. Bare raise without a captured active exception remains unavailable, as do chained raises. Normal value returns are not created for escaping raises.

Python binding scope format 3 uses the same alias parser as data-flow capture, including tree-sitter's `as_pattern_target(identifier)` representation. Alias bindings shadow normalized global names and get explicit cleanup masks. A reassignment inside the handler is visible there; the cleanup mask still prevents a stale inferred type outside it. Unrelated imports remain resolvable. Core name binding remains a conservative syntax/type subset, not complete Python compiler/evaluation-order semantics.

Value normalization format 3 accepts frozen capture formats 5, 6 and 7. Plain compatible functions can compare across formats. Context-bearing functions are excluded on both sides when capture formats differ, so analysis-model enrichment cannot impersonate source changes. Same-format handler contexts normalize comments, NFKC spelling and position-only shifts with the ordinary node/edge coverage guards.

The existing independent query limits remain. Capture additionally caps each protected/region completion inventory and handler-route expansion at 128 states, with bounded filter/region/context depth and function work. Environment copies consume capture work. Overflow is explicit and cannot prove absence. Database/JSON loading and full-response byte/memory/time budgets remain separately unqualified.

Capabilities advertise handler paths while keeping type/filter evaluation, full exception/CFG/heap/alias semantics, predicate/iteration feasibility, termination, runtime paths and full CPG unproven. Asynchronous/resource failures, arbitrary operator/iterator/protocol effects, exceptional uninitialized reads, complete class matching, dynamic/chained exception forms and broader languages remain open.
